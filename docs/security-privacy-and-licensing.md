# 安全、隐私与授权边界

- 更新日期：2026-10-26
- 状态：初始代码审查结论；正式发行前仍需人工和法律层面确认

## 总体原则

当前目标平台是 macOS，不代表历史移动端功能已经清除。代码中仍有网络、云存档、激活、日志上传和支付相关实现，发行或恢复功能前必须确认真实数据流和服务状态。

未经用户明确授权：

- 不新增或启用网络请求。
- 不连接历史生产服务试探。
- 不新增账号、登录、分析、广告、支付、云同步或在线 AI。
- 不申请新的系统权限。
- 不输出、保存或提交凭据和用户数据。

Development Build 当前启用了 `AllowDebugging`，运行时会打开托管调试监听并发送 Unity Player discovery 组播。这只允许用于受控的本地开发环境；发布构建必须关闭 Development Build/Script Debugging 并重新检查网络行为。

## 已发现的历史能力

### 网络访问

`Assets/Scripts/Base/GamePHP.cs` 使用 `UnityWebRequest` 实现历史服务端通信，涉及云存档、激活、日志或平台校验。文档和日志中不得复制真实服务地址、参数或用户标识。修改前应确认服务所有权、TLS、认证、超时、重试、错误提示和数据保留政策。

### 云存档

`GameUserData` 与 `GameSLCloudUI` 保留历史云存档数据和 UI。正式启用前需确认用户认证、数据结构、加密、删除、冲突解决、恢复策略、离线行为和隐私要求。默认验证只覆盖本地存档。

### 日志上传

代码存在把错误信息交给历史网络层的路径。日志可能包含堆栈、设备环境和运行状态。启用前必须列出字段并脱敏，禁止上传存档、稳定设备标识或凭据。

### 激活与支付

工程保留 Android 激活、iOS 条件编译校验以及 `DllImport("__Internal")` 支付/原生接口。不得自行迁移、模拟、绕过或删除；去留属于产品和合规决定。

## 本地数据

玩家设置通过 `PlayerPrefs` 保存，进度和战斗状态主要位于 `Application.persistentDataPath`。

- 不在日志中打印完整存档或用户输入。
- 处理损坏存档时保留原文件，避免静默覆盖。
- 迁移必须支持失败回退并说明备份位置。
- 不把真实用户存档加入 Git、测试夹具或问题附件。
- 未来引入沙盒、签名或公证流程时，验证持久化目录迁移行为。

## 密钥与签名资产

不得写入仓库、文档、日志或汇报：Apple Developer 凭据、Developer ID/Distribution 私钥、`.p12`、描述文件、证书私钥、公证凭据、API key、token、密码、真实账号、云存档标识和支付凭据。

正式签名应使用本机 Keychain 或受控 CI Secret，并另建不含秘密值的发布清单。
