## 目标与边界

界面显示“简单 / 普通 / 困难”。普通完全对应现有“简单模式”，困难完全对应现有“困难模式”；两档原数值、奖励、AI和判定不变。新增简单面向轻松体验剧情，减少练级、补给、角色死亡及反复读档。不自动完成探索，不承诺自动取得隐藏结局或全部道具。

拟允许修改：GameSetting/GameHelpUI的模式枚举与显示，GameDefine的显式模式分支，新增集中管理的简单档策略，以及经验、战斗伤害结算、回合恢复、熟练度奖励门槛的必要调用点和专项验证。实际文件白名单在用户确认后实施前再次列出。

不修改：原关卡/剧情/地图/资源配置、普通和困难的数值与规则、敌人出场和目标、物品/合成配方、原始角色成长表、存档二进制字段顺序、签名和工程配置。剧情强制死亡、撤离和关卡事件不能被通用“不死”逻辑拦截。

## 已确认的现状

- GameSetting.GameMode：Normal=0，Hard=1；当前显示为简单模式/困难模式，模式保存在全局PlayerPrefs的mode键，并非每个普通存档独立保存。
- GameDefine.Difficulty：令P为实际累计熟练度，Normal为P/60+0.8，Hard为max(P/60+0.9,1)。敌人初始化在GameBattleUnit.updateUnitData中按此缩放HP、MP、Str、Vit、Avg、Int；友方NPC的该系数另设1。
- Avg还参与移动力，GameBattleUnitAI的选目标权重也读取Difficulty。因此不能把整体Difficulty随意乘很小的倍率后称作“只减攻防”。
- HPMax>=2500会设isBoss，Boss标记又影响部分诅咒/特殊攻击处理。直接砍血可能改变身份判定，初版不采用此做法。
- 困难还影响道具攻击是否奖励经验（GameBattleAttackResult两个addExp分支）；普通/困难保留这些既有差异。
- GameDefine.MAX_EXP=500，MAX_LEVEL=99。GameBattleUnit的addExpSkill两个重载、addExpCure、addExpDamage分别产生辅助/伤害/治疗经验；存在等级差衰减和最少经验，临时经验及持久经验使用short，放大后要覆盖连续升级、99级及溢出边界。
- GameBattleJudgment.UpdateProficiency只有ReloadBattleCount==0时才把本关ProficiencyStage计入总熟练度。GameOverUI现有“重试战斗”会增加重试计数，不需要另造一个返回标题再读档的流程。
- Stage31对应地图事件仍检查P>=25、指定武器、剧情标志等，难度降低不能等同于满足这些条件。

不叠加降低升级经验门槛；例如原100经验行动在简单获得120，不再同时把500/级降成其他值。经验在一个统一入口只加成一次，实际到账和界面数字一致。自动恢复、战后恢复不给经验，不额外生成自动刷经验循环。技能的原等级/五魂条件仍须满足，不直接解锁全部招式。

保留普通档敌人的基础属性、Boss身份、移动、射程、AI和免疫；新增辅助放在明确的结算层，不能既缩敌人攻击属性又重复乘最终减伤。需审核普攻、法术、反击、反伤、固定伤害、持续异常和环境伤害路径，区分敌对伤害、治疗、主动技能HP代价和剧情指令。剧情指令及剧情表演战斗不能被通用HP钳制拦住，否则可能无法推进。

场景切换、简单→普通/困难时必须停止简单档自动恢复等临时规则；不增加濒死保护次数或其存档状态。

31幕P>=25门槛、其他装备/探索条件保持。简单只宽免“重试整关奖励作废”，不会凭空送25点，也不自动满足每关目标。普通/困难继续使用原ReloadBattleCount==0规则。

## 第二阶段可选项，不建议首版全部堆上

- **落后角色追赶**：低于队伍平均等级2级以上的参战者获得额外经验，优先解决治疗/辅助角色掉队；上限和分配另定，不能把2倍经验在多个入口重复叠加。
- **固定平均成长**：简单升级时取原成长范围期望值，降低为了刷随机成长而读档的动机；不改原成长表，只有简单分支采用。是否采用需另确认。
- **战斗金币×1.5**：只调整明确的战斗奖励，不乘买卖、剧情定额、宝箱或关键道具。先看经验与免费恢复是否已足够，避免经济过度膨胀。
- **关卡目标提示**：对护送、指定人物、回合目标给简洁提示；提示需逐关核对，不能显示未经确认的剧情剧透。

## 切换难度的真实影响

伤害、自动恢复为临时规则，切回原模式后停止。**已经获得的经验、等级、学习技能、熟练度不会回退**。因此允许旧档改简单继续，但不能称为完全可逆或保证切回后的角色强度与从未开过简单一致。若未来需要竞争/评分，应另设计，不在本轮扩展。

## “重试”与读档、五蕴的代码核对

- 此处“重试”特指败阵后GameOverUI的onReloadBattle：增加ReloadBattleCount/All，clearBattle清本场战斗，重新激活本关、初始化宝物与单位，并由GameBattleTurn.start从第1回合开始。此路径没有调用load/loadBattle，不是读取用户选择的手动存档，也不能称作完整战前快照回滚；队员重新引用GameUserData当前UnitBase。本方案只宽免该计数导致的熟练度整关不入账规则。
- 手动载入普通存档、手动载入战斗档是另外的读文件路径，按所选文件恢复相应状态；不能把两者统称为败阵重试。
- 五蕴五项为迅、烈、神、魔、魂。GameUnitLevelUpData.levelUp中每升一级固定BaseSpiritPower+=2；GamePowerUI.onAskUIClick从未分配点扣除并分别加入SpiritPower五项，每项现有界面上限100。经验不直接分配给五项。
- 成长表技能同时要求角色等级及五项SpiritRequest达到各自门槛。经验→角色升级→取得可分配点→玩家分配五项→满足等级和五项条件，这些是不同步骤。
- 当前GamePowerUI分配确认只更新数值；成长表技能学习检查位于levelUp，分配点数本身不立即执行补学。普通流程中加到门槛后，可能还需下一次升级才学习；剧情/其他途径授予技能另当别论。
- 简单档经验×1.2会让升级及取得五蕴点更快，但每级仍2点，不等于每级4点，也不自动替玩家分配或忽略技能条件。是否另加五蕴点、降低门槛或增加加点后补学属于新方案选择，尚未获准，不在本轮实现。

3. 接入简单专属熟练度宽免；验证护送对象、主角死亡判负、脚本死亡/撤离、关键Boss、连续集火、读档/重试及模式切换。保留正常死亡、所有关卡目标与Stage31的24/25边界。

初始数值是待调参方案，不是已完成的平衡或“必定不死”证明。目标是正常完成关卡目标即可轻松推进，允许少量失误且不被整关熟练度惩罚迫使读旧档；故意跳过目标、主动牺牲技能或剧情失败仍按原规则处理。

- 回合恢复每个新我方回合一次，先处理原中毒结算，再恢复存活者；当前回合读档不重复补给。开始新战斗本就满HP/MP，因此第1回合不重复恢复。
